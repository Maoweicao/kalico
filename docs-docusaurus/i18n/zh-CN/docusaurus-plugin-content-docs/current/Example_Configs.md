# 示例配置

本文档包含向 Kalico GitHub 仓库（位于 [config 目录](../config/)）贡献示例 Kalico 配置的指南。

请注意，[Klipper 社区 Discourse 服务器](https://community.klipper3d.org)也是查找和共享配置文件的有用资源。

## 指南

1. 选择适当的配置文件名前缀：
   1. `printer` 前缀用于由主流制造商销售的原装打印机。
   2. `generic` 前缀用于可能在许多不同类型打印机中使用的 3d 打印机板。
   3. `kit` 前缀用于按照广泛使用的规范组装的 3d 打印机。这些"套件"打印机通常与普通"打印机"不同，因为它们不是由制造商销售的。
   4. `sample` 前缀用于可以复制粘贴到主配置文件中的配置"片段"。
   5. `example` 前缀用于描述打印机运动学。此类配置通常仅与新型打印机运动学的代码一起添加。
2. 所有配置文件必须以 `.cfg` 后缀结尾。`printer` 配置文件必须以年份后跟 `.cfg` 结尾（例如 `-2019.cfg`）。在这种情况下，年份是该打印机大致的销售年份。
3. 不要在配置文件名中使用空格或特殊字符。文件名应仅包含字符 `A-Z`、`a-z`、`0-9`、`-` 和 `.`。
4. Kalico 必须能够无错误地启动 `printer`、`generic` 和 `kit` 示例配置文件。这些配置文件应添加到 [test/klippy/printers.test](../test/klippy/printers.test) 回归测试用例中。在适当的部分中按字母顺序添加新的配置文件。
5. 示例配置应为打印机的"原装"配置。（在主 Kalico 仓库中跟踪太多"自定义"配置是不现实的。）类似地，我们仅为具有主流受欢迎程度的打印机、套件和板添加示例配置文件（例如，应至少有 100 台在活跃使用）。对于其他配置，请考虑使用 [Klipper 社区 Discourse 服务器](https://community.klipper3d.org)。
6. 仅指定给定打印机或板上存在的设备。不要指定特定于你的特定设置的设置。
   1. 对于 `generic` 配置文件，仅应描述主板上的那些设备。例如，向"generic"配置添加显示配置节是没有意义的，因为无法知道该板是否会连接到该类型的显示器。如果板具有特定的硬件端口以方便可选外设（例如 bltouch 端口），则可以为给定设备添加"注释掉的"配置节。
   2. 不要在示例配置中指定 `pressure_advance`，因为该值特定于耗材，而非打印机硬件。类似地，不要指定 `max_extrude_only_velocity` 或 `max_extrude_only_accel` 设置。
   3. 不要指定包含主机路径或主机硬件的配置节。例如，不要指定 `[virtual_sdcard]` 或 `[temperature_host]` 配置节。
   4. 仅定义利用给定打印机特定功能的宏，或定义为给定打印机配置的切片软件通常发出的 g-codes。
7. 在可能的情况下，最好使用与现有配置文件相同的措辞、短语、缩进和节顺序。
   1. 每个配置文件的顶部应列出用户在"make menuconfig"期间应选择的微控制器类型。它还应引用"docs/Config_Reference.md"。
   2. 不要将字段文档复制到示例配置文件中。（这样做会增加维护负担，因为更新文档需要在许多地方进行更改。）
   3. 示例配置文件不应包含"SAVE_CONFIG"节。如有必要，将 SAVE_CONFIG 节中的相关字段复制到主配置区域中的适当节。
   4. 使用 `field: value` 语法而不是 `field=value`。
   5. 添加挤出机 `rotation_distance` 时，如果挤出机具有齿轮机构，最好指定 `gear_ratio`。我们期望示例配置中的 rotation_distance 与挤出机中齿轮的周长相关——通常在 20 到 35mm 范围内。指定 `gear_ratio` 时，最好指定机构上的实际齿轮（例如，优先使用 `gear_ratio: 80:20` 而非 `gear_ratio: 4:1`）。更多信息请参阅[旋转距离文档](Rotation_Distance.md#using-a-gear_ratio)。
   6. 避免定义设置为默认值的字段值。例如，不应指定 `min_extrude_temp: 170`，因为这已经是默认值。
   7. 在可能的情况下，行不应超过 80 列。
   8. 避免在配置文件中添加归属或修订消息。（例如，避免添加"此文件由...创建"之类的行。）将归属和更改历史放在 git 提交消息中。
8. 不要在示例配置文件中使用任何已弃用的功能。
9. 不要在示例配置文件中禁用默认安全系统。例如，配置不应指定自定义 `max_extrude_cross_section`。不要启用调试功能。例如，不应有 `force_move` 配置节。
10. Kalico 支持的所有已知板都可以使用默认串口波特率 250000。不要在示例配置文件中推荐不同的波特率。

示例配置文件通过创建 GitHub "pull request"提交。也请遵循[贡献文档](CONTRIBUTING.md)中的说明。
