# 多微控制器归零和探测

Kalico 支持一种机制，可以在限位开关连接到一个微控制器的同时，其步进电机位于不同的微控制器上进行归零。此功能被称为"多微控制器归零"。当 Z 探针位于与 Z 步进电机不同的微控制器上时，也会使用此功能。

此功能可用于简化布线，因为将限位开关或探针连接到更近的微控制器可能更方便。但是，使用此功能可能会导致步进电机在归零和探测操作期间出现"过冲"。

过冲的发生是由于监控限位开关的微控制器与移动步进电机的微控制器之间可能存在消息传输延迟。Kalico 代码旨在将此延迟限制在不超过 25ms。（当多微控制器归零被激活时，微控制器会发送定期状态消息，并检查在 25ms 内收到相应的状态消息。）

因此，例如，如果以 10mm/s 的速度归零，则可能出现高达 0.250mm 的过冲（10mm/s * .025s == 0.250mm）。配置多微控制器归零时应注意此类过冲。使用较慢的归零或探测速度可以减少过冲。

步进电机的过冲不应对归零和探测过程的精度产生不利影响。Kalico 代码将检测过冲并在其计算中加以考虑。但是，重要的是硬件设计能够处理过冲而不会对机器造成损坏。

为了使用此"多微控制器归零"功能，主机计算机与所有微控制器之间必须具有可预测的低延迟。通常，往返时间必须持续小于 10ms。高延迟（即使是很短的时间）可能会导致归零失败。

如果高延迟导致失败（或检测到其他通信问题），Kalico 将引发"通信超时导致归零失败"错误。

请注意，具有多个步进器的轴（例如 `stepper_z` 和 `stepper_z1`）需要位于同一微控制器上才能使用多微控制器归零。例如，如果限位开关位于与 `stepper_z` 不同的微控制器上，则 `stepper_z1` 必须与 `stepper_z` 位于同一微控制器上。
